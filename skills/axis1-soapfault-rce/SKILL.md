# axis1-soapfault-rce: Apache Axis 1.x SOAP fault class instantiation (CVE-2026-90436)

Under an **authorized** engagement only. This skill classifies the target as
affected / not affected / hardening-relevant (endpoint discovery; fault payloads are never shipped), using the
vendored PoCs and lab under `scripts/poc/axis1-soapfault-rce/`. Run every PoC against the
lab first (`scripts/poc/axis1-soapfault-rce/lab/setup.sh`), then once against the
authorized target, and compare the outputs.

## Running the bundled scripts

Paths such as `scripts/poc/axis1-soapfault-rce/...` are relative to this skill's base directory
(`<base>/scripts/poc/axis1-soapfault-rce/`). The skill directory is read-only for agent processes,
so never write into it:

- `poc/` verifiers only read and print; run them in place, for example
  `python3 <base>/scripts/poc/axis1-soapfault-rce/poc/<script>`.
- Before running `lab/setup.sh` (it writes its config files next to itself), copy the
  lab into the task working directory: `cp -r <base>/scripts/poc/axis1-soapfault-rce/lab ./axis1-soapfault-rce-lab`
  and run `./axis1-soapfault-rce-lab/setup.sh` from there.

## What the bug is

- Apache Axis 1.x is an end-of-life Java SOAP engine. When it processes a
  SOAP **fault** element, it reads the `exceptionName` the message supplies
  and instantiates that class reflectively.
- An unauthenticated attacker can therefore make the JVM load and construct
  an arbitrary class on the application's classpath. With a suitable class
  available, this becomes code execution.
- Per-service authentication does not protect the service, because Axis
  parses the envelope before any service-level auth runs.
- In the wild:
  - N-able N-central was exploited together with the "4EverAble2Shell"
    bugs to drop crypto-miners.
  - Rapid7 saw exploitation against Confluence Data Center around
    2026-11-13. Confluence uses Axis for its SOAP and XML-RPC APIs.
  - A public Python PoC exists.
- Scores: CVSS 3.1 9.8 (CVE record), CVSS 4.0 9.3 (Atlassian). Red Hat
  rates it lower because exploitation needs a usable class.

## Affected / not affected

- Affected: every Axis 1.x through 1.4, and any product that bundles it.
  There is no fixed Axis 1.x release.
- The fix comes from the product vendor (for example, Atlassian's patched
  Confluence releases), or from rebuilding with the July 2026 upstream
  commit.
- Not affected: Axis2/Java, and applications where the Axis servlet is not
  reachable.

## Hard gates

1. **Authorization**: the target is in scope.
2. **No class-instantiation payloads on live targets**: these are lab-only.
   For a bundled product (Confluence, N-central), reproduce against the same
   product version in the lab.
3. **Program policy**: the KEV listing is days old, and vendor product
   patches may be newer still. Check the policy before claiming.
4. **Compromise check**: with host access, hunt before advising (see below).
5. **Lab first**: run `scripts/poc/axis1-soapfault-rce/lab/setup.sh` and the PoC against
   the lab until its output is understood, then run it once against the
   authorized target and keep both outputs as evidence:
   ```bash
   python3 scripts/poc/axis1-soapfault-rce/poc/verify_exposure.py --target https://{host}
   ```

## Detection workflow

1. **Find Axis endpoints**: check `/axis/`, `/axis/services`, `/services/`,
   `/servlet/AxisServlet`, and `*?wsdl`. Axis 1 WSDLs contain the comment
   `Generated by Apache Axis version: 1.4`. For Confluence, check
   `/rpc/soap-axis/confluenceservice-v2?wsdl` and `/rpc/xmlrpc`.
   ```bash
   curl -sk "https://{host}/rpc/soap-axis/confluenceservice-v2?wsdl" | grep -o 'Apache Axis version: [0-9.]*'
   ```
2. **Pre-auth reachability**: if the endpoint returns a WSDL or a SOAP fault
   without a session cookie, it is reachable before authentication.
3. **Product version**: for Confluence, use the footer or
   `/rest/applinks/1.0/manifest` to get the version, then compare it with
   Atlassian's fixed releases for CVE-2026-90436. For N-central, compare
   against N-able's advisory. For custom apps, find `axis-1.4.jar` (or
   `axis.jar` with a 1.x manifest) in `WEB-INF/lib`.
4. Classify:
   - **affected**: Axis 1.x is reachable before auth and the product is
     unpatched;
   - **hardening-relevant**: Axis 1.x is present but sits behind auth or a
     network boundary;
   - **not affected**: no Axis 1.x, or the vendor-patched build.

## Hunting (host access)

- Access logs: POSTs to Axis endpoints whose body contains `<soapenv:Fault>`
  or `exceptionName` in a **request**. Legitimate clients do not send
  faults.
- The Java process spawning shells, `curl`/`wget`, or miners.
- Unexpected outbound connections from the application host.

## Mitigation to cite

- Apply the product vendor's fix (Confluence, N-central). Migrate custom
  services to Axis2 or another SOAP stack.
- Interim: block Axis paths at the reverse proxy (`/rpc/soap-axis/`,
  `/axis/`, `/services/`) when SOAP is not needed.
- Interim: drop requests whose body contains a SOAP `Fault` element.

## Reporting

- Title: Unauthenticated remote class instantiation in Apache Axis 1.x
  (CVE-2026-90436).
- Include: the endpoint URL, the WSDL Axis version string, the product
  version, pre-auth evidence, and the KEV status.
